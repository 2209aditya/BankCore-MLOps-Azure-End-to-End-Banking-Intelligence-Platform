🤖 AI integration — banking use cases

The following AI modules are deployed as independent ML services, each serving a distinct banking function with real-time and batch inference modes.

Fraud detection
Real-time transaction scoring using gradient boosting + graph neural networks. Flags suspicious patterns, card-not-present fraud, and account takeovers within a single API call.
latency <80ms
Credit risk scoring
ML-powered credit decisioning using transactional behavior, account history, and bureau data. Produces risk scores and explainable feature breakdowns via SHAP values for regulatory compliance.
SHAP explainability
Customer churn prediction
Identifies customers at risk of leaving using engagement signals, product usage, and lifecycle stage. Powers proactive retention campaigns triggered via Azure Logic Apps.
30-day horizon
Product recommendations
Collaborative filtering + content-based models suggest relevant banking products — savings accounts, loans, insurance — personalized to each customer's financial profile and life events.
360° customer view
AML / compliance
Anti-money laundering model monitors transaction networks for structuring, layering, and integration patterns. Generates Suspicious Activity Reports (SARs) with supporting evidence chains.
SAR auto-draft
AI banker assistant
LLM-powered internal assistant for relationship managers — retrieves customer 360 summaries, flags risk signals, and drafts communication templates using Azure OpenAI Service.
Azure OpenAI
How AI transforms bank operations: AI integration reduces manual review load on fraud teams by automating first-pass triage, improves credit decision consistency, and enables personalized banking at scale. Regulatory models produce audit-ready evidence trails, reducing compliance overhead while improving detection rates across all financial crime typologies.

🔄 CI/CD — Azure DevOps pipeline

1
Developer push to feature branch
Code pushed to Azure Repos triggers CI automatically. Runs flake8, black, isort, mypy, and pytest across unit and integration test suites.
2
Docker build + push to ACR
FastAPI inference image built and pushed to Azure Container Registry. AML environment registered with updated dependencies.
3
AML training pipeline triggered (on merge to main)
Challenger model trained on latest curated dataset. Metrics logged to MLflow — accuracy, AUC, F1, KS statistic, and Gini coefficient for credit models.
4
Champion vs challenger evaluation
Challenger compared against production champion. Promotion blocked if challenger fails to exceed champion AUC by threshold or fails fairness checks.
5
Staging deployment + smoke tests
Challenger deployed to AKS staging namespace. Smoke tests fire synthetic transactions and verify prediction latency, schema, and edge case handling.
6
Manual approval gate → production blue/green
ML lead approves promotion in Azure DevOps. Blue/green swap on AKS production with instant rollback capability. Model registered in AML Model Registry with full lineage.

🚀 Getting started

Prerequisites

# Required tools Python 3.11+ Azure CLI az extension add -n ml Docker kubectl Make (optional)

1. Clone and configure

git clone https://dev.azure.com/your-org/bankcore-mlops/_git/bankcore-mlops cd bankcore-mlops cp .env.example .env # Fill in your Azure subscription details

2. Provision infrastructure

az deployment group create \ --resource-group rg-bankcore-dev \ --template-file infra/main.bicep \ --parameters infra/parameters/dev.parameters.json

3. Submit a training job

# Fraud detection model — AML pipeline az ml job create \ --file src/pipelines/fraud_training_pipeline.yml \ --workspace-name aml-bankcore-dev \ --resource-group rg-bankcore-dev # Or Python SDK v2 python src/pipelines/fraud_training_pipeline.py

4. Deploy to AKS

az aks get-credentials --resource-group rg-bankcore-dev --name aks-bankcore-dev kubectl apply -f k8s/deployment.yaml kubectl apply -f k8s/service.yaml kubectl apply -f k8s/hpa.yaml kubectl get pods -n bankcore
